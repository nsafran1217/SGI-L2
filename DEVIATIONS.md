# Differences from SGI's 1.62.0 tools

Every way these tools behave differently from SGI's binaries. The first
table is from the reconstruction: what the originals relied on that current
systems no longer have. The second lists the modern changes (MODERN.md);
each one updated tests/golden/ in its commit. (SGI's own bugs, kept or
fixed, are in ORIGINAL_BUGS.md.)

## From the reconstruction

| Where | Difference | Why |
|---|---|---|
| `common/sys/sysutils.h` `struct _sem_t`, `struct _queue_t` | Bigger than the original (48 bytes). | They embed `pthread_mutex_t`/`pthread_cond_t`, which are bigger in modern glibc than in glibc 2.1.3. Both are in-memory only, so nothing depends on the old layout. |
| `l3/gui` (l2gui) | Built with FLTK 1.3 (from `../refs/fltk`, see `../retools/setup_fltk.sh`) instead of FLNX, SGI's Nano-X port of FLTK 1.0. The windows are regenerated by FLUID from reconstructed `ui/*.fl` files. | SGI's FLNX tree (`l3/flnx`) is not available, and FLTK 1.3 keeps the 1.0 API l2gui uses while running on current X11 (and on other platforms). |
| `l3/gui` (l2gui) | The windows are FLTK subwindows of one 320x240 top-level window. The command window is not modal (the main window is deactivated while it is up, as in the original). Showing a window makes it the screen's last child (`l2gui_show()`). | The original's windows were Nano-X windows on a 320x240 screen: the L2's panel, or one X window titled "Microwindows". FLTK honours only top-level modal windows, and offers clicks to subwindows in child order rather than stacking order. |
| `l3/gui/l2gui.cc` | Labels use FLTK size 12. | FLNX asked Nano-X for Arial TrueType fonts the L2 never had and fell back to Nano-X's 13-pixel System font; FLTK's default size 14 is too big for the 320x240 layouts. |
| `l3/gui/fl.h` `fl_sleep()` | Waits on a timeout instead of looping on `Fl::wait(t)`. | FLTK 1.0's `Fl::wait(t)` returned the time left; later versions do not. |
| `l3/gui/flboxtype.cc` (added) | Flat, up, down and round boxes are redrawn FLTK 1.0's way: an inactive widget keeps its fill color, only its bevels and text are grayed. | FLTK 1.1 and later fade the fill as well, which grays the white status area and logo while the command window is up; the original (FLTK 1.0) left them white. |

## Modern changes

| Where | Difference | Why |
|---|---|---|
| `l2`, all clients | No authentication. `l2` never asks a client for a password (a password sent anyway is ignored); its consoles have no login; the `password` command, `l2 -password` and `l2passwd` are gone. The clients have no `--pw` and never prompt: an L2 that asks for a password gets an empty one. | For hobbyist installations on a private network. The Router protocol keeps its password messages, so the wire stays compatible. |
| `l2` console commands | No control of the host: `halt_l2`, `reboot_l2`, `shell` (and its pty code), `ip` and `dhcpserver` are gone; `date <date>` and `date tz <zone>` are always refused (as the original did unless `-pc`); `l2dbg dump` (reading l2's memory at any address) is gone. | The host is managed as any other machine; a console that runs shells and reboots it is a liability on a network. |
| `l2 -l1sim`, `-l1sim_manual` | Gone: they print the usage. | They started SGI's `l1sim.linux`, which was never shipped. `-net` (L1s over TCP, which the simulator used) stays. |
| `l2 -serial` | Gone, with the PPP-framed serial and terminal-server L1 links. The usage line lists the real options (the original's said `-enet` for `-net`). | Hobbyist L1s are on USB; the serial link was for L1s without one. |
| `l2cmd`, `l2term`, `l2gui` | No direct L1 connections: `--dev` and `--serial` (an L1's serial port, PPP-framed, locally or on a terminal server) and `--sc`/`--scdev` (the system controller device of an SN system's Linux) are gone; a client always talks to an L2. | The L2 (this `l2`) is how a hobbyist installation reaches its L1s. |
| `l2 -pc` | Gone, with the PC L2's modem console on the second serial port (`smp modem baud`). `-discover` is the rest of what it did; `quit` always exits `l2`, and `date sync` always warns that the timezone is not synced (the non-PC behaviour). | No hobbyist L2 has the modem. |
| `l2dbg mstat`, `mmap`, `mreset`, `menable`, `mdisable`, `mmalloc`; `--mtrace` (all tools) | Gone, with `minfo.c`. | They hooked glibc's malloc, which glibc 2.34 no longer allows; AddressSanitizer and Valgrind do this job now. |
| `l2` settings and log | The NVRAM image (`./.l2_NVRAM`) is gone. Settings are `key = value` lines in `l2.conf` (`-c <file>`, `SGI_L2_CONFIG`, or `$STATE_DIRECTORY/l2.conf` under systemd, else `./l2.conf`), rewritten line by line when a console command changes one; the log is `l2.log` next to it, plain text. The IP address, DHCP server, timezone, modem and password settings are gone, the USB debug level is no longer kept across restarts, and `-syncssn` is gone (edit the file). `nvram reset` resets the file to the defaults; the log keeps its entries (and a log that wrapped is shown, which the original's was not). | A hobbyist can read and edit the settings. |
| `l2` messages at levels 0–2 | `L3: <file> line <n> ; ` (ORIGINAL_BUGS.md). | The original printed an address, different every run. |
| `l2 -usb` (the default) | L1s are opened with libusb (`l1usb.c`), not through SGI's `sgil1` kernel driver: no driver to build, and with the udev rule no root. Devices are numbered first free as the driver did, and report the same USB paths (`-usbpath` is unchanged); a port's device name is `usb<n>` instead of `/dev/sgil1_<n>`. The driver's revision checks are gone. | The driver needed building for every kernel (and on the Docker host). |
| `l2`'s stdin console | Only with `-console`, or when stdin is a terminal; at the end of its input it stops reading (the original read the end of a `/dev/null` stdin over and over, at 100% CPU). Without it, everything l2 prints also goes to stderr (the original sent it to the network sessions alone, when there were any). | A service has no terminal; its messages belong in the journal. |
| `l2api` (new) | An HTTP API to the L2 (README.md), a client like `l2term`: configuration as JSON, commands, power, the console as a WebSocket, events. SGI had none. | For scripts and a web interface. |
| `SCapi.c` `sn1SCInitPortAddr()` | Given `sn1SCGetL2Host()`'s own buffer as the host, it no longer copies the string onto itself (which emptied it). | Found by l2api. |
